# Development, forks, and self-hosted OAuth

This document is for contributors and maintainers. Normal users installing an official release should not need any Client ID, token, Google Cloud project, `.env` file, npm command, or build tool.

## Requirements

- Node.js 22 or newer.
- npm.
- Chrome 120+ for Google OAuth. Edge may be used for non-OAuth UI and attachment smoke tests, but does not support `identity.getAuthToken`.

## Install and test

```bash
npm install
npm run typecheck
npm run lint
npm test
npm run build
npm run verify:dist
```

`dist/` is the production unpacked extension. A debug build with detailed performance logging can be produced with `npm run build:debug`.

## Production Client ID

The official production build uses the maintainer's Chrome Extension OAuth Client ID. Installed-app OAuth client IDs are public identifiers and are expected to be present in client code. They are not Client Secrets.

Never add an access token, refresh token, Client Secret, private key, credentials file, or Google password to the repository, environment template, build output, tests, or logs. The account-chooser implementation stores only its short-lived access token in `chrome.storage.session`; never move it to local/sync storage.

## Configure a fork or development OAuth client

Use a separate Google Cloud project for development or a fork. Do not reuse the production project for unreviewed scopes or experimental clients.

1. Create a Google Cloud project.
2. Enable **Google Photos Picker API** (`photospicker.googleapis.com`).
3. Configure Google Auth Platform / OAuth consent for the intended audience.
4. Add only:

   ```text
   https://www.googleapis.com/auth/photospicker.mediaitems.readonly
   ```

5. Create an OAuth client of type **Chrome Extension** for the deterministic Chrome-profile fallback.
6. Use the extension item ID generated by your manifest public key. The official source key generates `igacbcmbkglkglkindhcpmagafnboolj`; replace the key and client together if your fork needs a different identity.
7. To support real account selection, also create an OAuth client of type **Web application**. Add this exact authorized redirect URI (including the trailing slash):

   ```text
   https://igacbcmbkglkglkindhcpmagafnboolj.chromiumapp.org/
   ```

   Do not put the Web Client Secret in this project. The extension uses the documented browser access-token response and stores no refresh token.

8. Configure both public client IDs locally:

   ```bash
   npm run configure-oauth -- "YOUR_CHROME_CLIENT_ID.apps.googleusercontent.com" "YOUR_WEB_CLIENT_ID.apps.googleusercontent.com"
   ```

9. Rebuild and reload the extension.

The helper writes only public client IDs to ignored `.env.local`. Never copy the Web Client Secret into the extension.

## Authorization architecture

- With a Web OAuth client, user-initiated connect/account-change calls `launchWebAuthFlow` with `prompt=select_account`; page-load prewarm only reads the existing `chrome.storage.session` token and never opens login UI.
- Without a Web OAuth client, the fallback explicitly passes the visible Chrome profile account ID to `getAuthToken`. The UI labels this as the current Chrome account and never claims that Reconnect can choose another account.
- A 401 clears the rejected provider token. Chooser mode requires a new user-initiated account selection after expiry; it never stores a refresh token.
- Disconnect clears local provider state, revokes the chooser token through Google's endpoint when available, and stores a non-sensitive disconnect preference.

## Architecture preservation rules

Changes must preserve:

- standby Picker session prewarming;
- `chrome.storage.session` recovery;
- atomic session consumption;
- server-provided expiration and polling settings;
- MV3 alarm refresh;
- minimized Picker-page preload;
- OAuth/API fallback;
- ChatGPT SPA handling and attachment injection;
- cancellation and session cleanup.

Do not add legacy Google Photos Library scopes, remote executable code, analytics, or a token backend.

## Microsoft Edge compatibility

Microsoft documents `identity.getAuthToken` as unsupported in Edge and recommends `identity.launchWebAuthFlow` as the alternative. The production client in this repository is a Chrome Extension OAuth client and must not be silently repurposed for an unreviewed web authorization redirect flow.

An Edge-capable release requires a separately designed PKCE-capable public-client flow, an owner-configured compatible Google OAuth client and redirect URI, updated OAuth verification materials, and dedicated security tests. Until those inputs exist, the extension returns a localized compatibility message in Edge without exposing the raw browser error.
