# OAuth, privacy, and architecture

[简体中文](OAUTH_PRIVACY_AND_ARCHITECTURE.zh-CN.md)

This document explains how Google Photos for ChatGPT works, what the current Google OAuth warning means, what data stays local, and what data necessarily goes to Google or ChatGPT.

## Current OAuth verification status

The extension is functional, but the maintainer's Google OAuth application has **not yet completed the production verification and publishing work required for unrestricted public use**.

Depending on the Google Cloud project's current state, Google may show one of these messages during sign-in:

- “Google hasn't verified this app” or a similar unverified-app warning;
- a notice that the app is in testing;
- an access-denied message for accounts that are not configured as Test Users;
- a warning that the app requests access to Google Photos Picker data.

This warning is generated by Google because the OAuth consent configuration is not yet fully verified or published. It is not generated by ChatGPT and it is not hidden or bypassed by this extension.

Testers should continue only when all of the following are true:

1. The extension was installed from this repository or its official release page.
2. The consent screen names **Google Photos for ChatGPT**.
3. The only Google Photos scope shown is:

   ```text
   https://www.googleapis.com/auth/photospicker.mediaitems.readonly
   ```

4. The tester recognizes the Google Cloud project or has been explicitly invited as a Test User.

The remaining verification work is tracked in [GOOGLE_OAUTH_VERIFICATION.md](GOOGLE_OAUTH_VERIFICATION.md). Until it is complete, this project must not claim that every Google Account can authorize without a warning.

## Why two public OAuth client IDs exist

OAuth client IDs identify an application; they are public client configuration, not passwords or Client Secrets.

- The **Web application client** is used with `chrome.identity.launchWebAuthFlow` and Google's `prompt=select_account`. It allows the user to choose which signed-in Google account owns the Photos library to open.
- The **Chrome Extension client** remains as a deterministic Chrome-profile fallback for development and compatibility recovery.

The fixed extension redirect is:

```text
https://igacbcmbkglkglkindhcpmagafnboolj.chromiumapp.org/
```

No Client Secret or refresh token is compiled into the extension.

## End-to-end data flow

```text
User clicks the Google Photos button
→ Google account chooser and OAuth consent
→ short-lived access token in chrome.storage.session
→ POST photospicker.googleapis.com/v1/sessions
→ official Google Photos Picker opens
→ user explicitly selects media and presses Done
→ extension polls the session using Google's polling configuration
→ extension lists only the selected media items
→ selected bytes travel directly from Google's media host into browser memory
→ Blob/File objects are handed to the active chatgpt.com attachment interface
→ Picker session is deleted and temporary in-memory data is released
```

The project has no maintainer-operated backend in this flow.

## What remains local

- Picker job state, expiration, polling configuration, and window/tab identifiers are temporary browser-session data.
- The chooser-mode access token is kept only in `chrome.storage.session` and is removed on disconnect or browser-session end.
- Selected photo bytes are represented as in-memory `Blob` and `File` objects.
- The extension does not intentionally write photos to Windows Downloads.
- The project has no analytics, telemetry, advertising SDK, or remote executable code.

## What leaves the device

The extension cannot perform its function without communicating with the services chosen by the user:

- Google receives OAuth, Picker-session, and selected-media requests.
- Google-provided media hosts return the selected photo bytes.
- ChatGPT receives the selected files when the extension hands them to the active attachment interface.

The project maintainer does not receive these tokens, photos, filenames, or ChatGPT conversation data because there is no project-controlled server. Google and OpenAI still process data under their own terms and privacy policies. No software can honestly promise zero security risk; this project's narrower claim is that it does not add a maintainer-controlled collection or transmission path.

## OAuth and Picker lifecycle

1. A real account-selection action starts only after a user click.
2. The extension validates the OAuth `state` value and the fixed redirect origin.
3. The token must include the exact Picker scope.
4. “Connected” appears only after a real Picker `sessions.create` request succeeds.
5. A standby session may be created after authorization so the next Picker opens faster.
6. A standby session is atomically consumed once and checked against Google's `expireTime`.
7. Switching or disconnecting accounts closes active Picker windows and deletes obsolete sessions.
8. `401` responses clear the rejected token; the extension does not keep a refresh token.

## ChatGPT attachment path

The content script does not rely on generated CSS class names. It attempts, in order:

1. a semantic `input[type=file]` path using `DataTransfer`;
2. observation of dynamically inserted file inputs;
3. a standards-based drag-and-drop handoff;
4. verification that ChatGPT's attachment UI reacted.

ChatGPT is a changing third-party SPA, so future UI changes may require maintenance.

## Storage and retention

| Data | Location | Retention |
|---|---|---|
| Short-lived chooser access token | `chrome.storage.session` | Browser session, disconnect, or token rejection |
| Picker session/job metadata | `chrome.storage.session` | Browser session or job cleanup |
| Explicit disconnected preference | `chrome.storage.local` | Until reconnect or uninstall |
| Selected photo bytes | Browser memory | Active transfer only |
| Client IDs and extension public key | Source/build | Public application identity |

The extension does not store Google passwords, Client Secrets, refresh tokens, private keys, or photo bytes in persistent extension storage.

## User controls

- **Choose another Google account** starts Google's official account chooser and discards the previous standby session.
- **Disconnect Google Photos** clears local authorization state and requests token revocation from Google's official endpoint when available.
- Closing the Picker cancels the current selection and triggers session cleanup.
- Uninstalling the extension removes its local extension storage.
- Google-account access can also be reviewed or revoked from the user's Google Account security settings.

## Security review boundary

The repository includes source code and a reviewable `dist/`. Production builds use Manifest V3 and a local-only extension Content Security Policy. Contributors and testers must never publish real access tokens, private Google Photos URLs, personal filenames, account screenshots, or credentials in GitHub Issues.
